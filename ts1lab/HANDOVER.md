# VWSフォトショブリッジツール 引き継ぎメモ（クラウドセッション → PC のセッション）

VWS のテロップファイル（.ts1）と Photoshop を相互変換する実験の、現時点の状態です。
新しいセッションはまずこのファイルと [FORMAT.md](FORMAT.md)、[README.md](README.md) を読んでください。

## 目的（ユーザーの要望）

1. .ts1 を解析して Photoshop で再現する（編集できるテキストレイヤとして）
2. Photoshop で作ったテロップを .ts1 で書き出して VWS で使う
3. フォントを正しく特定・設定する（最優先）

Photoshop の文字＋境界線（ライブテキスト）と VWS の差 3.45% は、設定ではこれ以上詰められない。理由は VWS の描き方にある
（FORMAT.md「VWS の描き方」）: 縁は丸ではなく「文字面を 1px 刻みでずらして重ねた」階段状の形、さらに上下 2 ラインの平均がかかる。
Photoshop の境界線（丸）とアンチエイリアスでは同じ絵にならない。加えて Photoshop はテキストの色をガンマ 1.45 で混ぜる
（カラー設定「テキストカラーをガンマでブレンド」。アプリ全体の設定なので触っていない）。

そこで **PSD の構成を変えた**（ユーザーの「わずかな差もなくしたい」への対応）:

- 一番上: 「VWSの見た目（正確な画像・編集不可）」＝ `○○_再現.png`（VWS と同じ描き方で作った画像）。**表示**
- その下: 「編集用テキスト：…」＝ 編集できるテキスト＋境界線。**非表示**（PSD → TS1 はこのレイヤを読む。非表示でも読める）
- 文字を直すときは画像レイヤを非表示にしてテキストを表示・編集 → `3_PSDをTS1に変換` → `○○_確認.png` が VWS の見た目
- **レイヤーカンプ**を 2 つ付けた（ウィンドウ > レイヤーカンプ）: 「① VWSの見た目（正確な画像）」「② テキスト編集（Photoshop の文字）」。
  ワンクリックで切り替えられる。保存時の初期表示は①。ユーザーに「どちらを初期表示に？」と聞いたら「全部やって」だったので両方持たせた
  （注意: ExtendScript で `layerComps.add()` の戻り値に `apply()` すると先に登録したカンプが適用される。登録時点の状態がそのまま残るので apply しない）

保存した PSD を Photoshop で開いて表示される絵と VWS の PNG の差は **0.94%（全画素の 81% が完全一致）**。最初は 6.9%、ライブテキストは 3.45%。
`render.py` を VWS の描き方に作り直したので、`_再現.png`・`_確認.png`・`_画像レイヤ.psd` も同じ精度になった。

検証スクリプトの注意: Photoshop の DOM でレイヤを `activeLayer` にすると非表示のレイヤが表示に戻る。表示状態を確かめるときは
保存済み PSD を開き直して、何も選択せずに PNG 保存する。

`alert` は、ラッパ側で `$.global.alert` を差し替えれば止まらない。照合の手順: JSX を実行 → 結果を PNG 保存 → VWS の PNG と比較。

## VWS の描き方をさらに特定（2026-11-12 午後。`vwsrender.py`）— VWS の PNG と 99.57% の画素が完全一致

ユーザーの「目指せ 99.9%」を受けて、VWS の PNG の画素値から描き方を逆算した。`_再現.png` / `_確認.png` / PSD の画像レイヤは `vwsrender.py` で描く。
見本でインクのある 120,057 画素中 **99.569% が完全一致**（違う画素 517、平均差 0.027%。それまでは完全一致 81%・平均差 0.94%）。

確定したこと（詳しくは `vwsrender.py` の冒頭）:
1. VWS は GDI で 8 倍サイズに塗っている。輪郭の点は `(int)(座標 × 8)`（0 方向へ切り捨て）。直線だけの字（回・出・個）は画素単位で完全一致
2. GDI の塗りの規則 = 整数座標の点で内外判定（numpy では多角形を +0.5 ずらして中心判定にすれば同じ。本物の GDI と全点一致を確認）
3. 字の原点: 行の先頭字からの距離 × 0.9999 を 1/8px に四捨五入（7 字目で 1/8px の段差）。0.99991 / 0.99989 では悪化
4. 曲線: 整数のまま半分ずつ割る再帰分割（中点は 0 方向へ切り捨て）。VWS の輪郭から頂点が区間の端点・中間点・1/4 点にあることを確認
5. 上下 2 ラインの足し算 k[y] = m[y] + m[y+1]。字ごとに上端を整数行に丸め、その上にはみ出す行は切る
6. 縁 = k のずらし重ねの最大値（i² + j² ≤ 41〜44）。VWS の文字面から作ると縁のアルファが **全画素で完全一致**
7. 色 = floor(縁色′ + (文字色′ − 縁色′) × k / 128)、アルファ = min(255, 2k)。色′ は 8bit 値 + (R 0.90〜0.95, G 0.81, B 0.10)。見本の 129 色すべて再現

**未確定（残り 517 画素の原因）: 曲線を「割るのをやめる条件」**。今は 2 階差分の 2 乗和 ≤ 72（8 倍格子）を採用。
候補ごとの食い違い画素（全 16 字の合計）: 2 乗和 ≤72: 266 / 和 ≤11: 271 / 弦の中点と制御点の距離の和 ≤5: 277。
字によって最良の式が違う（個・人・ら は「距離の和 ≤5」で 0、の は「2 乗和 ≤72」で 8）ので、本当の式は近い別の形。
2048 単位や実数での判定は大きく悪化（1,784）。「い」は どの式でも 33 残る（曲線とは別の原因の可能性。未調査）。
調査用スクリプトは作業用一時フォルダにあり、リポジトリには入れていない（必要なら同じ手順で作り直す: VWS の PNG から
色 → k_f を逆引き → 下から m[y] = k[y] − m[y+1] で 1 ラインぶんの塗り m を逆算 → 字ごとにモデルと比較）。

Photoshop のライブテキスト側の設定（STRONG など）と PSD の構成は変えていない。**新しい描画での PSD の作り直しと往復の再確認はまだ**。

## 追加サンプルが必要な解析

VWS で同じ文言のまま設定を 1 つだけ変えて別名保存した .ts1 を `ts1tool.py diff A.ts1 B.ts1` で比べると保存場所が分かる。

- 2 行テロップ（改行コード、行の縦位置）
- 半角英数を含むもの（送り幅）
- 縁の色だけ / 太さだけ変えたもの、影・二重縁
- 左揃え・右揃え（SCLS の 2 が中央揃えかどうか）
- 別フォント（フォント番号の対応表を増やす。ウインクスL7 を使うならその .ts1 が必要）

## 主なコマンド

```
pip install -r requirements.txt
python run.py to-ps  見本.ts1        # → 見本_再現.png / 見本_画像レイヤ.psd / 見本_Photoshop用.jsx
python run.py to-ts1 テロップ.psd     # → テロップ_VWS用.ts1 / テロップ_確認.png
python run.py identify 見本.ts1      # 字形から PC 内のフォントを特定して フォント表.json に登録

python ts1tool.py compare 見本.ts1 VWS出力.png --diff 差分.png   # VWS 出力画像と照合
```

## 注意

- 実機（VWS）での確認は本番データを避け、テスト用の環境で行う
- 色は B G R A 順（`ts1core.COLOR_ORDER`）。見本の縁は青 #122FE7。VWS の PNG 書き出しでの色の入れ替えは無い
- **ユーザーから VWS の書き出し PNG が来たら、聞き返さずに PNG を正解として自分で照合・判断する**（ユーザーの希望）。
  `ts1tool.py compare` で .ts1 と、Photoshop の出力（COM で JSX を実行して PNG 保存）とも直接比べる。PNG から分からないこと（VWS 上のフォント名表示など）だけ聞く
- 字間（ACSP）は「その文字の直前」に効く。Photoshop のトラッキングは「その文字の後ろ」なので 1 文字ずらして変換している
